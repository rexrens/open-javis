### [x] Critical-1：OpenAICompatAdapter 工具调用参数截断

> ✅ 已修复并验证（2026-09-02）：发射推迟到完成边界（finish_reason / 更高 index + JSON 完整 / 流耗尽 flush）；
> 新测试 `test_openai_compat_stream_tool_call_accumulates_across_chunks`；独立复现 4 变体
> （finish 边界 / 无 finish 耗尽 / 空参数 / 双工具调用交错）全通过；修复前同场景实测输出 `'{}'`（红）。

- 位置：`javis/llm/openai_compat.py` `stream()` 内 tool-call 发射循环（约 160-180 行）
- 现象：`tc_id` 首次非空即发完整 block（start + delta + end），`emitted` 标记后**后续
  arguments 分片全部丢弃**。标准 OpenAI 流式（首片 id+name、arguments 跨 chunk 分片）下，
  工具 block 的 arguments 截断为首片累积值——通常是 `'{}'`。
- 复现：fake SDK 流 `[id+name] → args 分片 ×2` 喂 `adapter.stream()`，输出
  `tool-call-delta 'read_file' '{}'`，真实参数丢失。
- 定性：**既有 bug 被忠实移植**（旧 `javis/engines/harness/llm_adapter.py` 同逻辑，非本次
  回归）；但重构后 OpenAICompatAdapter 是唯一生产 adapter，主路径受影响。
- 测试缺口：`tests/test_harness/test_async_llm.py` 只测了 `_parse_openai_chunk` +
  `_tool_call_snapshots` 的孤立累积，未测 `stream()` 全链路发射。
- 修法建议：工具 block 发射推迟到"完成边界"——(a) 出现更大 index 的分片、(b) `finish_reason`
  到达、(c) 流耗尽——三处之一统一 flush 已累积的 tc_map 条目；发射后清 emitted。
  补一个全链路回归测试（fake SDK 分片流，断言最终 ToolCallBlock.arguments 完整）。
- 注意：缓存路径（`_save_cached` 的 collected）会跟着发射逻辑变，回放语义保持一致即可。

### [x] Important-2：configurable-provider 目录注册簇损坏（runtime.py，三处叠加）

> ✅ 已修复并验证（2026-09-02）：`DirectoryRegistrationHandle` 持 `held` 列表（对齐
> `AdapterRegistrationHandle.owned`），disposer 遍历 `list(held)` 副本 + 身份校验；
> 3 个新测试（独立释放 / 多条目 dispose / replace 不泄漏）；修复前 3 场景实测全失败（红），
> 修复后全通过（绿）。

- 位置：`javis/llm/runtime.py` `_directory_effect` / `_commit_directory` /
  `DirectoryRegistrationHandle.replace`（约 214-262 行）
- 现象（均已复现）：
  1. disposer 清空**整个** `_directory` 而非自己持有的条目（dsh 只释放 `held`）：
     注册 A、B 后释放 A → B 的条目一起没了（或见第 2 条直接崩溃）。
  2. disposer 在 `for entry in self._directory.values()` 迭代中 `pop` → 目录 ≥2 条目时
     `RuntimeError: dictionary changed size during iteration`。
  3. `replace()` 传 `held=[]` → 旧路由不释放：`a→b` 替换后目录为 `['a','b']`（旧条目泄漏）。
- 根因：dsh 用闭包变量 `held` 由 `commit` 更新（`held = detached`）；javis port 的
  `DirectoryRegistrationHandle` 没有自己的 held 列表，disposer 闭包直接遍历全局 `_directory`。
  对照同文件 `AdapterRegistrationHandle`（`owned` set 方案）是正确的。
- 影响面：`register_configurable_providers` / `list_configurable_providers` /
  `register_model_discovery` / `discover_models` **零测试覆盖**，当前生产代码零调用——
  属"全量 port 面"上的潜在损坏，不修则未来插件一用就踩。
- 修法建议：给 handle 加 `held: list`（对照 AdapterRegistrationHandle.owned），
  `_commit_directory` 继续 mutate 该列表；disposer 遍历 `list(self._held)`；
  `replace` 传 `self._held`。补测试：双注册互不牵连、≥2 条目 dispose 不崩、
  replace 换名不泄漏、dispose 幂等。

### [x] Important-3：`llm/stream` waterfall 契约与实现不符（二选一，需拍板）

> ✅ 已选 **(b) 改文档收敛契约** 并验证（2026-09-02）：runtime.py / __init__.py / stream() docstring
> 均改为"raw stream 可拦截，prepared dispatch 直接绑定注册"；新测试
> `test_prepared_dispatch_bypasses_llm_stream_waterfall` 钉住当前语义（assert seen == []）。

- 位置：`javis/llm/runtime.py` `stream()` / `prepare_call().stream` 闭包；
  `javis/harness/types.py` `GenerateOptions(frozen=True)`
- 偏差（均已复现）：
  1. **prepared 路径绕过 waterfall**：agent 循环主路径（`agent.py:432` `prepared.stream(request)`）
     不经过 `llm/stream` waterfall；dsh 的 `preparedCall.stream` 走
     `streamWithRegistration` → waterfall 内。
  2. **路由能力不可达**：dsh 的 routing middleware 靠就地改 `options.provider`；
     javis `GenerateOptions` 是 frozen dataclass → 实验直接 `FrozenInstanceError`；
     且 innermost lambda 忽略 payload（用闭包 options），替换 payload 也无效。
- 现状：javis 实际 retry 走 `agent/request-error`、routing 走 `agent/request`，
  **当前无功能损坏**；但 `runtime.py` docstring、`javis/llm/__init__.py`、README 架构图均声称
  "llm/stream waterfall over **every** streaming call (retry/replay/routing)"——过度承诺。
- 选项：
  - **(a) 修语义对齐 dsh**：prepared 闭包改走 waterfall（innermost 用 payload 续链，
    innermost 签名 `(payload, next)` 已就位）；middleware 路由改为"返回新 payload"约定
    （frozen options 不可就地改，需约定 next(payload') 或 innermost 读 payload）。
    成本：waterfall 语义要动 javis/cordis 或约定层，且 dsh 测试里 in-place 改法在 javis 永远
    不可用，文档要写清。
  - **(b) 改文档收敛契约**：waterfall 声明为"观察 + 流包裹"（现状可用），
    路由/重试明确归 `agent/request` / `agent/request-error`；删掉 "every streaming call"
    与 "routing" 字样（runtime.py:13、__init__.py:11、README:58）。
    成本：小；代价：放弃 dsh parity，未来想加 replay 类 middleware 要回头改。
- 建议：**先 (b) 后按需 (a)**——当前无消费者，(b) 消除误导即可；(a) 等真有路由需求再做。
